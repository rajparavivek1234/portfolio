Feature ETA Agent

Give it a feature request. Get a delivery date you can defend.

Before, a feature request ended with a date somebody typed. Nobody wrote down which teams and services it touched, the date had no assumptions behind it, and priority got argued again in every meeting.

Runs in your browser: four dependent tasks with PERT effort estimates (illustrative inputs)

01

The model reads

It quotes the ticket, finds the teams and services, maps dependencies, proposes sizes and asks at most five questions. It is never allowed to type a date.

02

The code calculates

Python engines turn PERT effort estimates into a schedule, run 2,000 Monte Carlo simulations to get P50/P80/P95 dates, find the critical path and score priority with RICE and WSJF. 42 checks run at every step.

03

People decide

Team leads accept or adjust, security signs off, and nothing is written to Jira or Slack without a human approval. Every plan is versioned and re-planned when something changes.

    production incidents

    Bugs I've chased down in production

    Every fix ships with evidence: before/after traces, verified on staging before release.

    INCIDENT #01

    First-poll race on a synchronous card processor

    symptom
    The gateway acknowledged sales, then answered the first status poll with "request not found". Our adapter declined while the processor captured the money.
    fix
    Moved the pending-code rule into one shared set for all five poll steps, added an unmapped-code warning, and documented the exhaustion path and its trade-off.
    proof
    Mocked and live traces before/after.
    INCIDENT #02

    Recurring charges failing at a gateway

    symptom
    Merchant-initiated renewals were declined because the off-session and network-transaction-ID rules only applied to subscriptions.
    fix
    Extended the merchant-initiated predicate to every stored-credential flow and normalized the network-transaction-ID format.
    proof
    Verified on staging before release.
    INCIDENT #03

    Webhook 5XX storm

    symptom
    A webhook endpoint returned 500 on events it should ignore, so the processor retried for days and flooded the alerts.
    fix
    Changed the ignorable-error path to a 204 ack and added a monitor that tells provider retries apart from real failures.
    proof
    Alert volume back to baseline.
